# 写 / 改回件模板(①写 `01-write-handoff.md` · ③改 `03-fix-handoff.md`;整块照抄,逐项填;缺项 = 回件不合格)

边写边落。件内只贴末行读数 / 摘录 + `.evidence/` 路径,命令全量输出不进件(行与**自写字节**两条红线,`flow-doc-budget` 量)。回件是你逐字打出来的:实测每 100 输出 token ≈ 1.3 秒墙钟,一份 40 KB 的回件 ≈ 4 分半纯打字。

**首行逐字写成 `# <轮名> 回件 · …`**(轮名 = 派单里「轮次 / 模型」那一行的字面,如 `③改二`)。件名归编排方随手起,`flow-round` 认领本轮回件靠的是这一行 —— **0.8.2 起认不出直接 RED**,不再按件名前缀猜:猜错的件名不会停在收工那一刻,它进状态档的每一次刷新(实测两批各错一次,一次是 14 行行行错)。

**〇 节不许留占位。** 被判停时也要在原位写下当下的实况,续轮**在原位补全**,别把结论补在末尾另起一节 —— 〇 是下游整轮唯一的跳读入口,占位留着,下一轮只能整读你这份件(实测 ④A 的〇节 52 字节占位 ⟹ ③改二 整读 33 KB)。
**热路径节(〇 + 丙栏)有字节红线**(`FLOW_DOC_BUDGET_HOTPATH`,收工判):判的不是你写了多少,是下游每一轮要重读多少。细节往甲栏与 `.evidence/` 挪,〇 与丙只留判据与指针;全文多长不在这条线上。

```

## 戊栏 · 给 flow-local.md 的新实录(踩到就写)
```
